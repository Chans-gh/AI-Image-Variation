# 实现决策与来源

1. **开发范围**：只实现 Skill 01 v1.3。SPEC 00/03 来自用户本地同系列 v1.1 资料包，用于契约兼容；不开发 Skill 02，不自动启动内容流程。
2. **版本冲突**：旧规范的 tile_min_edge_default / 单格像素下限 / 旧 seam_score 阈值未进入 v1.3 第 17 章；不能用其推翻 Provider-Native Resolution。新产物按 v1.3 保持 image-artifact 1.0，加 dimension_execution，读 1.0/1.1；旧 1.1 schema 原样保留，不伪造旧 seam_score。
3. **文档勘误**：§16.1 的 DIRECTION_RULE 来源写为 16.10，实际为 16.13；抽取器按实际标题提取。输入原规范原样保存在 specs，勘误仅记在此处。
4. **宿主边界**：模型原生尺寸、文件、整数切图用确定性 Python；语言模型做 P1-01/02/03/04/06，图像模型执行 P1-05/07/08，宿主多模态能力做 P1-09。没有伪造的“语言模型规则规划器”或凭像素自动宣布主体一致的质检器。
5. **逐步执行**：每个 step 至多一次生图，产出原始字节后必须等待绑定任务、修订、计划、索引、尝试和图片哈希的 QA。无视觉工具则保持 validating，不能交付 qualified tiles。示例自动审核器仅限 mock 环境。
6. **不可变产物**：原生文件与有效图分开；完成包在 staging 中验证后再重命名，旧修订不覆盖。补生成只操作失败索引，保存成功图与原锚点。
7. **失败清单**：旧 schema 不允许 images 为空，也不允许失败槽位省略虚假的尺寸/哈希。因此未产生任何有效图时只交付失败 job 状态；部分序列的 images 仅列真实成功文件，failed_frames 保存缺帧索引，image_count 保持目标总数。
8. **包自哈希**：delivery-package.json 覆盖全部其他文件。清单自身不能包含其自身 SHA256；ZIP 位于产物目录外，避免递归清点。
9. **凭据**：未创建、复制或导出任何 Key。兼容适配器从调用方注入秘密或本地 env 名称解析；本机 Codex OAuth 由既有选定 Skill 内部读取。此阶段不配置官方 OpenAI API 项目。
10. **能力与容差**：样例档案保持 unverified；Mock 档案不可用于 live Provider。≤1% 的两种容差是设计默认，真实模型回归未通过前不宣称冻结。
11. **测试照片**：用户提供的原图与本地路径只保存在 gitignored .work；不写入公开 Skill 包、测试夹具或仓库。真实生成的可交付图片另存 artifacts；不把合成图当真实样图。
